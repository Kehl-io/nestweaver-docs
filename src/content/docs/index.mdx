An agent that starts from the file tree reads until the context window is full, and still may not have the caller, the type, or the test. Search finds the string. It does not say what reaches this function, or what a diff puts at risk.

NestWeaver parses the repository once into symbols, calls, and imports, and answers from that graph. The answer is a short, ranked neighborhood — the same one you can open in the browser — instead of a pile of files.

![NestWeaver web UI overview: files on the left, the graph in the center, details on the right](/images/web-ui.png)

The overview above is a small sample project. The center is the graph. The right-hand panel is empty until you select a symbol. The green chip says the view is local and current.

## First session

1. [Install the CLI](/getting-started/) with npm. No Rust toolchain required.
2. [Index the repo you are in](/getting-started/quick-start/) with `nestweaver index --repo .`
3. Ask for one symbol: `nestweaver context <name>`
4. Open `nestweaver ui` and select that symbol.

[What NestWeaver is](/getting-started/overview/) explains the three surfaces — CLI, editor, and web UI — before the command reference.
